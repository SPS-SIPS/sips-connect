# SPS Connect 2.0.1

## Changes

- Domestic outgoing payments use the bank's existing localId/EndToEndId for durable retry deduplication. txId remains optional and is generated by SPS Connect when omitted.
- Retries return the original payment references and state without resubmitting, including simultaneous submissions across instances.
- Unresolved recovery failures remain pending rather than being presented as confirmed network rejection.
- Status enquiries reject untrusted or mismatched network evidence before completion processing and preserve non-final statuses for reconciliation.

## Deployment requirements

Startup automatically applies `AddDomesticOutgoingLocalId`. Tests cover upgrading historical null and duplicate EndToEndIds without modifying the old records. Index creation still needs an appropriate deployment window for production database size and locking.

Confirm that each bank supplies a unique localId per instruction and preserves it across retries. Upgrade domestic writers together; do not mix old writers that omit the new database key with the new version.

## Known limitations

When the network has confirmed settlement but bank completion notification fails and exhausts retries, manual reconciliation may still be required. These fixes prevent that condition from being falsely presented as network rejection; they do not separate notification-delivery state into an independent recovery workflow. Do not resubmit the payment to repair notification delivery.

One existing captured-recall certificate test fails in the local environment and was reproduced on unchanged main. All 237 core tests (7 existing skips), 22 focused status-safety tests included in that core suite, and 8 PostgreSQL domestic payment/migration tests passed; the API suite had 250 passes and that one pre-existing failure.
